## 3. 技术方案

### 3.1 表命名规范

#### 3.1.1 命名规则

| 规则 | 说明 | 示例 |
| ---- | ---- | ---- |
| 小写字母 | 表名统一使用小写字母 | `user_info` |
| 下划线分隔 | 多个单词使用下划线连接 | `order_detail` |
| 表前缀 | 表名使用 `t_` + 模块名；各微服务独立数据库，不再使用 `sys`/`biz` 分区前缀 | **示例** `t_{module}` |
| 禁用保留字 | 避免使用数据库保留字 | 禁止 `order`, `group` 等 |

#### 3.1.2 表名后缀约定

| 类型 | 命名规范 | 示例 |
| ---- | ---- | ---- |
| 模块主表 | `t_{模块名}` | **示例** `t_{resource}`、`t_role` |
| 关联关系表 | `t_{模块名}_rel` 或 `t_{实体1}_{实体2}_rel` | **示例** `t_role_rel` |
| 日志/流水表 | `t_{模块名}_{动作}` 或 `t_{模块名}_log` | **示例** `t_{resource}_log`、`t_login_log` |
| 平台幂等表 | `sys_biz` | 业务幂等记录（各领域库各建一份，见 [微服务调用规范](./微服务调用规范.md) §3.4；固定表名，不纳入 `t_{module}` 命名） |

> 各微服务使用独立数据库，表名无需 `sys_`/`biz_` 前缀区分域；DTM 屏障表 **`sys_barrier`**（`gitee.com/hq_project/yomi-boot/sql/mysql/barrier.sql`）等框架表使用固定表名，不纳入本规范的 `t_{module}` 命名。

### 3.2 字段设计规范

#### 3.2.1 主键设计

```sql
`id` bigint NOT NULL COMMENT '主键ID',
PRIMARY KEY (`id`)
```

主键不允许自增，统一由应用层雪花算法生成。

#### 3.2.2 必备字段

每张表必须包含以下统一审计字段：

| 字段名 | 类型 | 默认值 | 说明 |
| ------ | ---- | ------ | ---- |
| `id` | `bigint` | `NOT NULL` | 主键ID |
| `create_time` | `datetime` | `CURRENT_TIMESTAMP` | 创建时间 |
| `create_by` | `bigint` | `NULL` | 创建人ID |
| `update_time` | `datetime` | `CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | 更新时间 |
| `update_by` | `bigint` | `NULL` | 更新人ID |
| `delete_time` | `datetime` | `NULL` | 删除时间 |
| `delete_by` | `bigint` | `NULL` | 删除人ID |

`delete_time`、`delete_by` 为统一审计字段。是否采用软删除以业务需求为准，不能仅因保留字段就默认使用软删除。

#### 3.2.3 字段类型选择

| 数据类型 | 推荐用法 | 说明 |
| -------- | -------- | ---- |
| `tinyint` | 二值技术标记、布尔开关 | 禁止用于业务枚举字段 |
| `int` | 数量、计数 | 中等范围整数 |
| `bigint` | 主键、大数值ID | 避免溢出风险 |
| `varchar(n)` | 字符串、业务枚举编码 | 状态、类型、来源等闭集业务字段优先使用 `varchar` |
| `text` | 长文本 | 文章内容、JSON 数据 |
| `datetime` | 时间 | 统一使用 `datetime` |
| `decimal(m,d)` | 金额 | 精确计算，避免精度丢失 |

#### 3.2.4 字段注释规范

```sql
`status` varchar(20) NOT NULL DEFAULT 'ENABLED' COMMENT '状态：ENABLED-启用，DISABLED-禁用',
`user_type` varchar(20) NOT NULL COMMENT '用户类型：ADMIN-管理员，USER-普通用户'
```

### 3.3 索引设计规范

#### 3.3.1 索引命名规则

| 索引类型 | 命名规则 | 示例 |
| -------- | -------- | ---- |
| 主键 | `PRIMARY` | 自动命名 |
| 唯一索引 | `uk_字段名` | `uk_username` |
| 普通索引 | `idx_字段名` | `idx_create_time` |
| 联合索引 | `idx_字段1_字段2` | `idx_user_status` |

#### 3.3.2 索引设计原则

1. 优先为选择性高的字段建立索引。
2. 联合索引字段顺序按查询频率和过滤效果排列。
3. 单表索引数量保持克制，避免过多冗余索引。
4. 对高频列表查询优先考虑覆盖索引。

### 3.4 DDL 编写规范

#### 3.4.1 建表模板（**示例**表名 `t_{resource}`，字段随业务域调整）

```sql
CREATE TABLE `t_{resource}` (
  `id` bigint NOT NULL COMMENT '主键ID',
  `code` varchar(50) NOT NULL COMMENT '业务编码',
  `name` varchar(50) DEFAULT NULL COMMENT '名称',
  `status` varchar(20) NOT NULL DEFAULT 'ENABLED' COMMENT '状态：ENABLED-启用，DISABLED-禁用',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `create_by` bigint DEFAULT NULL COMMENT '创建人ID',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `update_by` bigint DEFAULT NULL COMMENT '更新人ID',
  `delete_time` datetime DEFAULT NULL COMMENT '删除时间',
  `delete_by` bigint DEFAULT NULL COMMENT '删除人ID',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_code` (`code`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='资源表示例';
```

#### 3.4.2 修改表规范

```sql
-- 示例
ALTER TABLE `t_{resource}` ADD COLUMN `extra` varchar(255) DEFAULT NULL COMMENT '扩展字段' AFTER `name`;
ALTER TABLE `t_{resource}` MODIFY COLUMN `name` varchar(100) DEFAULT NULL COMMENT '名称';
ALTER TABLE `t_{resource}` ADD INDEX `idx_extra` (`extra`);
ALTER TABLE `t_{resource}` DROP COLUMN `old_field`;
```

## 4. 检查清单

- [ ] 表名使用小写字母和下划线，统一以 `t_` 前缀开头
- [ ] 每张表包含统一审计字段
- [ ] 主键非自增，字段注释完整
- [ ] 业务枚举字段未使用 `int` / `tinyint` 乱存语义值
- [ ] 索引命名和数量符合规范
- [ ] 建表与改表 SQL 可直接用于结构评审或迁移脚本编写
- [ ] 文档中不混入具体编程语言、对象映射或应用层实现口径

---

## 5. 禁止项

- 禁止将业务枚举字段设计为难以理解的数字魔法值。
- 禁止因为历史实现习惯保留无意义字段。
- 禁止把非数据库层约定写成数据库规范正文。
- 禁止继续沿用与数据库设计无关的实现约定作为默认数据设计口径。
