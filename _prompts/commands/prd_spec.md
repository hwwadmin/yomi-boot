---
description:产品业务需求文档生成
---

1. **定位 `_prompts`（强制）**：按顺序尝试：① 当前项目根 `_prompts/`；② 环境变量 `YOMI_PROMPTS_ROOT`（`yomi-boot` 仓库根，或该根下含 `_prompts` 的父路径）；③ Git submodule / 同级克隆的 `yomi-boot/_prompts/`；④ 依赖库 `yomi-boot`（`gitee.com/hq_project/yomi-boot`，经 go.mod / `replace` / module cache 解析到仓库根）包内的 `_prompts/`。均未找到则**终止**并列出已尝试路径。定位成功后，`_prompts/skills`、`knowledge` 均相对该根；业务产物（`_doc/`、`_feat-doc/`、`_task-doc/`、`_quality-doc/`、`_ipc-doc/`）写入**当前业务工程根**（boot 库维护模式除外）。

2. 基于当前会话中此前讨论的需求、决策与补充说明，总结生成一份产品业务性质的 PRD 文档。

3. 生产过程需要基于第一性原理和对抗性审查进行思考，并参考**当前业务工程** `_doc/` 中已有的产品需求文档，确保业务口径一致（勿把 `_prompts/knowledge/` 当作产品 PRD）。

4. 文档应从产品与业务视角描述需求背景、目标用户、业务目标、使用场景、需求范围、业务流程、功能需求、业务规则、验收标准、非目标、风险及待确认事项。

5. 仅归纳已有讨论中能够确认的内容，不得凭空补充业务结论；假设、冲突和信息缺口必须明确标记为待确认。

6. 文档不得包含技术选型、系统架构、数据库、接口、代码实现、部署方案等技术细节。

7. 产物落盘至**当前业务工程** `_doc/` 目录，命名遵循团队惯例（如 `{YYYYMMDD}_{需求名称}-prd.md`）；若目标文档已存在，应结合当前讨论进行增量修订，避免覆盖仍然有效的业务内容。
