# 技能加载规则

---

## 核心原则

技能加载必须遵循**渐进式披露**原则，通过技能列表文档作为索引层，逐步获取具体技能内容。禁止绕过技能列表直接加载技能文档本体。纯规范、原则、基线类静态文档不应作为 Skill 加载，而应通过知识库索引加载。

---

## 1. 加载流程

### 1.1 标准加载路径

```
用户请求 → 查询技能列表 → 筛选匹配技能 → 获取技能目录 → 加载技能文档
```

### 1.2 详细步骤

1. **查询技能列表**
   - 读取 `_prompts/doc/Skill技能列表.md`
   - 获取所有已注册技能的元信息

2. **筛选匹配技能**
   - 根据任务需求，匹配技能的名称、描述、状态等字段
   - 确认技能状态为"已发布"或"发布中"

3. **获取技能目录**
   - 从技能列表的"目录地址"字段获取技能文档路径

4. **加载技能文档**
   - 根据获取的路径加载具体技能文档
   - 执行技能定义的任务

---

## 2. 禁止行为

### 2.1 禁止直接加载

❌ **错误做法**：
```
用户请求 → 直接搜索 _prompts/doc/skills/ 目录 → 加载技能文档
```

✅ **正确做法**：
```
用户请求 → 查询技能列表 → 获取目录 → 加载技能文档
```

❌ **错误做法**：
```
用户请求 → 从 _prompts/doc/skills/ 目录加载静态规范文档 → 当作 Skill 执行
```

✅ **正确做法**：
```
用户请求 → 判断是执行流程还是静态规范 → 静态规范走知识库索引，执行流程走技能列表
```

### 2.2 原因说明

- **渐进式披露**：避免一次性加载大量不必要的技能文档
- **状态管理**：技能列表记录了技能的状态，未发布技能不应被使用
- **版本控制**：技能列表提供了版本信息，确保使用正确的技能版本
- **可追溯性**：通过列表可以清晰追踪技能的使用情况

---

## 3. 技能列表字段说明

| 字段 | 用途 | 必须检查 |
|------|------|----------|
| 技能列表登记 ID | 技能列表中的唯一标识 | 是 |
| 名称 | 技能名称，用于匹配 | 是 |
| 描述 | 技能功能描述，用于匹配 | 是 |
| 版本 | 技能版本号 | 是 |
| 目录地址 | 技能文档路径 | 是 |
| 状态 | 技能状态（开发中/测试中/待发布/发布中/已发布） | 是 |
| 作者 | 技能作者 | 否 |
| 创建日期 | 创建时间 | 否 |

---

## 4. 状态检查规则

在加载技能前，必须检查技能状态：

| 状态 | 是否可用 | 说明 |
|------|----------|------|
| 开发中 | ❌ | 技能正在开发，不可使用 |
| 测试中 | ❌ | 技能正在测试，不可使用 |
| 待发布 | ❌ | 技能待发布，不可使用 |
| 发布中 | ⚠️ | 技能正在发布，谨慎使用 |
| 已发布 | ✅ | 技能已发布，可正常使用 |

---

## 5. 执行检查清单

在加载任何技能前，AI 必须确认：

- [ ] 已读取技能列表文档 `_prompts/doc/Skill技能列表.md`
- [ ] 已根据任务需求筛选出匹配的技能
- [ ] 已确认技能状态为"已发布"或"发布中"
- [ ] 已从列表中获取技能的目录地址
- [ ] 未直接搜索或加载技能文档本体

---

## 6. 异常处理

### 6.1 技能不存在

如果在技能列表中未找到匹配的技能：
1. 告知用户当前没有可用的技能
2. 建议用户创建新的技能
3. 提供 Skill 创建规范路径：`_prompts/doc/knowledge/Skill创建规范.md`

### 6.2 技能状态不可用

如果匹配的技能状态不可用：
1. 告知用户技能当前状态
2. 说明该状态下的技能不可使用
3. 建议用户等待技能发布或联系技能作者

### 6.3 目录地址无效

如果技能列表中的目录地址无效：
1. 报告错误信息
2. 建议更新技能列表中的目录地址
3. 不尝试通过其他方式查找技能文档
