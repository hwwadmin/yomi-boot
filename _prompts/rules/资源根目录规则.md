# 资源根目录规则

---

## 1. 目的

统一 `_prompts` 的定位与加载方式，使业务工程 IDE **只需引入指令集**（`commands`），不必强制拷贝整棵 `_prompts`；同时保证执行前一定能解析到真实可用的 `_prompts` 根目录。

---

## 2. `_prompts` 定位流程（强制）

执行任何依赖 `_prompts` 的指令前，**必须先完成定位**，不允许跳过。按以下顺序查询：

| 优先级 | 位置 | 说明 |
| ---- | ---- | ---- |
| 1 | **当前项目根目录**下的 `_prompts/` | 业务工程若已挂载完整 `_prompts`，优先使用 |
| 2 | **当前项目依赖的外部库 `yomi-boot`**（`gitee.com/hq_project/yomi-boot`）包下的 `_prompts/` | 通过 go.mod / `replace` / module cache 等解析到的脚手架仓根目录 |

定位规则：

1. 先查当前项目；查不到再查依赖库 `yomi-boot`。
2. **不允许跳过定位**：未确认 `_prompts` 物理路径前，不得直接读取 Agent / rules / Skill / 知识库。
3. **两处均查不到则立即终止执行**，并向用户说明：已在当前项目与依赖库 `yomi-boot` 下均未找到 `_prompts` 目录，无法继续。
4. 定位成功后，后续文档中的 `_prompts/...` 一律解析到该物理根目录。

---

## 3. 资源根定义

| 符号 | 含义 |
| ---- | ---- |
| **当前项目** | 业务工程工作区根目录 |
| **gitee.com/hq_project/yomi-boot** | 脚手架依赖仓（本机 go.mod / `replace` 指向的 module 根） |
| **`_prompts`** | 按 §2 定位到的资源根目录（当前项目或 yomi-boot 包下） |

文档中写作 `_prompts/...` 时，均解析到 §2 已确认的物理路径。

---

## 4. 加载约定

1. **指令集**（`commands/*.md`）可放在业务工程 IDE 指令目录；执行时按 §2 定位 `_prompts`。
2. **Agent / rules / doc（知识库、Skill）** 只从已定位的 `_prompts/` 加载，禁止在未定位时凭空假设路径。
3. **业务产物**（如 `_doc/`、`_feat-doc/`、`_ipc-doc/`、`_task-doc/`、`_quality-doc/`）落在**当前业务工程**根目录，与 `_prompts` 无关。
4. 产品 PRD 等业务文档读当前工程 `_doc/`；脚手架知识库在 `_prompts/doc/knowledge/`，二者勿混用。

---

## 5. 强制效力

凡基于 `_prompts/agent/` 下 Agent 执行的任务，**必须先按 §2 定位 `_prompts` 并阅读本规则**，再加载其他 rules / Skill / 知识库。

涉及 Go 基础设施时，在遵守本规则定位 `_prompts` 后，还必须遵守 [基础库优先使用规则](./基础库优先使用规则.md)。
