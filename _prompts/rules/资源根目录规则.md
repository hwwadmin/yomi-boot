# 资源根目录规则

---

## 1. 目的

统一 `_prompts` 的物理落点，使业务工程 IDE **只需引入指令集**（`commands`），不必拷贝整棵 `_prompts`。

---

## 2. 资源根定义

| 符号 | 含义 |
| ---- | ---- |
| **yt-boot** | 脚手架依赖仓根目录（本机 go.mod / `replace` 指向的 module 根） |
| **`_prompts`** | **一律**指 `yt-boot/_prompts/`，不是业务工程根下的目录 |

文档中写作 `_prompts/...` 或 `yt-boot/_prompts/...` 时，均解析到上述脚手架仓路径。

---

## 3. 加载约定

1. **指令集**（`commands/*.md`）可放在业务工程 IDE 指令目录；执行时按本规则定位脚手架 `_prompts`。
2. **Agent / rules / doc（知识库、Skill）** 只从 `yt-boot/_prompts/` 加载，禁止要求业务仓维护第二份副本。
3. **业务产物**（如 `_doc/`、`_feat-doc/`、`_ipc-doc/`、`_task-doc/`）落在**当前业务工程**根目录，与 `_prompts` 无关。
4. 产品 PRD 等业务文档读当前工程 `_doc/`；脚手架知识库在 `_prompts/doc/knowledge/`，二者勿混用。

---

## 4. 强制效力

凡基于 `_prompts/agent/` 下 Agent 执行的任务，**必须先阅读并遵守本规则**，再加载其他 rules / Skill / 知识库。

涉及 Go 基础设施时，在遵守本规则定位 `_prompts` 后，还必须遵守 [基础库优先使用规则](./基础库优先使用规则.md)。
