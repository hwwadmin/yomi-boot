# 前端代码巡检

---

## 0. 基础信息
- **Skill 名称**: 前端代码巡检
- **描述**: 对指定前端页面或模块执行代码质量、UI 美化、性能优化三维巡检，结合项目规范输出问题清单或直接完成修复
- **作者**: zwei
- **创建日期**: 2026-06-02

---

## 1. 目标

- **做什么**：对指定前端代码范围执行三维巡检——代码质量（类型、结构、规范符合性）、UI 美化（视觉层次、交互反馈、设计语言一致性）、性能优化（加载、渲染、包体积），输出问题清单或在用户授权下直接修复。
- **为什么**：将代码质量、UI 美化和性能优化三个关联密切的前端治理动作合并为统一入口，避免各维度重复分析、交叉遗漏。
- **不做什么**：不涉及后端性能、不涉及 CDN 或网络层专项优化、不追求商城或营销类 C 端重装饰风格、不负责定义新的基础规范。

## 3. 技术方案

### 3.1 巡检维度

本 Skill 覆盖以下三个巡检维度，用户可单选或多选组合执行：

| 维度 | 聚焦 | 核心规范来源 |
| ---- | ---- | ------------ |
| 代码质量 | 类型系统、React 结构、页面拆分、国际化、注释符合性 | React代码规范、React分层规范、React注释规范、React状态管理规范、React国际化规范 |
| UI 美化 | 视觉层次、交互反馈、组件质感、设计语言一致性 | React分层规范 |
| 性能优化 | 路由加载、列表渲染、组件重渲染、包体积 | React代码规范、React分层规范 |

### 3.2 执行步骤

```text
开始
  ↓
1. 确认巡检范围与巡检维度（代码质量 / UI 美化 / 性能优化）
  ↓
2. 读取对应知识文档中的质量基线
  ↓
3. 按维度逐一执行检查：
   - 代码质量：ESLint / TypeScript / 定向代码审查 / 国际化检查
   - UI 美化：提炼页面视觉主轴 → 组件质感审查 → 交互反馈审查
   - 性能优化：瓶颈判断（加载/渲染/列表/包体积）→ 选择最小可验证手段
  ↓
4. 汇总跨维度问题清单，标注优先级与规范依据
  ↓
5. 输出问题清单，或在用户授权下直接修复
  ↓
6. 修复后重新执行相关检查并确认结果
  ↓
结束
```

### 3.3 代码质量检查重点

| 检查面 | 重点问题 |
| ------ | -------- |
| 类型系统 | `any`、无保护断言、闭集字段退化为 `string`、表单泛型缺失 |
| React 结构 | 组件职责混乱、Props 未定义、Hooks 依赖错误、类型导入不规范 |
| 页面拆分 | 页面主文件过长、列定义未下沉、类型散落、Hook 滥用 |
| 业务展示 | 时间字段格式化分散、状态判断直接比较字符串、`Transfer` 键类型不匹配 |
| 国际化接入 | React 场景误用 `translate()`、硬编码系统文案、语言切换后列定义或选项不刷新 |
| 注释符合性 | 文件头注释缺失、类型注释规格不一致、关键步骤缺注释 |

### 3.4 UI 美化检查与改造优先级

| 优先级 | 改造对象 | 目标 |
| ------ | -------- | ---- |
| P0 | 页面主标题区、欢迎横幅、主按钮 | 先建立视觉焦点与页面气质 |
| P1 | 卡片、输入框、表格、Tag、空状态 | 提升组件质感和信息层次 |
| P2 | 背景装饰、页面进入动画、图标徽章 | 在不干扰功能的前提下增加识别度 |

### 3.5 性能优化优先级

| 优先级 | 问题类型 | 优先手段 |
| ------ | -------- | -------- |
| P0 | 路由首屏慢 | 路由懒加载、拆分首包、优化 fallback |
| P1 | 列表和页面卡顿 | 限制重渲染、虚拟滚动、稳定列定义 |
| P2 | 组件重复渲染 | `React.memo`、`useMemo`、`useCallback` 的定向使用 |
| P3 | 包体积膨胀 | Bundle 分析、按需拆包、资源治理 |

### 3.6 输出要求

若本次执行为"只检查不修复"，输出必须至少包含：

- 巡检维度与范围
- 问题所在文件或模块
- 问题类型与对应规范来源
- 风险级别
- 最小修复建议

若本次执行为"允许直接修复"，则必须：

- 优先修复低风险、可机械验证的问题
- 代码质量修复后重新执行 ESLint / TypeScript 检查
- UI 改造后保证响应式、可读性和基础无障碍不退化
- 性能优化后重新执行构建或性能对比
- 在结论中说明已修复项与剩余风险项

## 4. 约束与规范

- [ ] 巡检必须以项目知识文档为唯一规范依据，禁止给出无来源的主观建议
- [ ] 未经用户允许，不扩大到无关目录或无关页面
- [ ] 有可执行校验时，修复后必须重新执行对应检查
- [ ] 代码质量维度：涉及系统文案时必须回看 React国际化规范；涉及注释补齐时必须回看 React注释规范
- [ ] UI 美化维度：稳定样式优先落在 CSS Modules 或 Ant Design Token，装饰元素不得影响点击、滚动和可读性
- [ ] 性能优化维度：必须先识别瓶颈再选择手段，禁止凭感觉到处加缓存，优化不能破坏组件职责和类型边界

## 5. 验收标准（DoD）

### 5.1 仅检查场景

- [ ] 已明确巡检维度和规范依据
- [ ] 已输出问题清单、风险级别和修复建议
- [ ] 已说明是否存在需要人工判断的边界问题

### 5.2 直接修复场景

- [ ] 已修复项均有对应规范依据
- [ ] ESLint / TypeScript 或等价检查已重新执行
- [ ] UI 改造后视觉层次明显提升，且不影响交互稳定性
- [ ] 性能优化后构建通过，未引入渲染回归或无关改动
- [ ] 未引入新的类型错误、构建错误或跨维度问题
