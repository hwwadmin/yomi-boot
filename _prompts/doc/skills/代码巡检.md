# 代码巡检

---

## 0. 基础信息
- **Skill 名称**: 代码巡检
- **描述**: 项目代码巡检的统一入口。在 **yt-boot 本仓**默认按基础库巡检；在业务仓可按范围分发到 Go代码巡检 或 前端代码巡检
- **作者**: zwei
- **创建日期**: 2026-04-16

---

## 1. 目标

- **做什么**：作为项目代码巡检的统一入口，接收巡检请求后按范围分发到 Go代码巡检 或 前端代码巡检 执行，汇总各维度巡检结果并输出统一报告。
- **为什么**：避免各巡检 Skill 需要单独调用，统一入口降低遗漏风险，汇总报告便于全局掌握项目质量。
- **不做什么**：不定义自己的巡检口径和检查规则。

---

## 2. 输入/依赖

### 2.0 调用方式与输入

调用本 Skill 时，需指定巡检范围（Go 后端 / 前端 / 全项目）以及是否允许直接修复。

> 示例调用：「请使用代码巡检 Skill，全项目巡检，只检查不修复。」

### 2.1 前置 Skill 依赖

| 名称 | 状态 | 说明 |
| ---- | ---- | ---- |
| Go代码巡检 | 已发布 | Go 后端分层架构、数据访问、事务、令牌、事件、注释巡检 |
| 前端代码巡检 | 已发布 | 前端代码质量、UI 美化、性能优化巡检 |

### 2.2 知识文档依赖

| 文档 | 关联点 | 说明 |
| ---- | ------ | ---- |
| `_prompts/doc/Skill技能列表.md` | Skill 索引 | 定位 Go代码巡检 和 前端代码巡检 |
| `_prompts/doc/knowledge/api/API编码适配规范.md` | 接口一致性 | Encoder 适配与本服务契约一致性检查依据 |

### 2.3 任务输入边界

- 若用户未指定范围，默认按全项目执行，分别调用 Go代码巡检 和 前端代码巡检。
- 不把 OpenSpec / SDD 文档混入巡检输入。

## 3. 技术方案

### 3.1 巡检流程

```text
开始巡检
  ↓
1. 确认巡检范围（Go 后端 / 前端 / 全项目）
  ↓
2. 按范围分发：
   - Go 后端 → 调用 Go代码巡检 Skill
   - 前端 → 调用 前端代码巡检 Skill
   - 全项目 → 依次调用两个 Skill
  ↓
3. 收集各 Skill 输出的问题清单
  ↓
4. 汇总为统一巡检报告并落盘
  ↓
结束巡检
```

### 3.2 分发规则

| 巡检范围 | 分发目标 | 说明 |
| -------- | -------- | ---- |
| 本仓（yt-boot） | Go代码巡检（基础库维度）+ 优先对照 Go基础库检查规范 | 检查本仓库各能力包；无业务 services / 前端目录则跳过对应项 |
| 业务仓 Go 后端 | Go代码巡检 | 检查业务工程 `services/*`（或等价可部署单元） |
| 业务仓前端 | 前端代码巡检 | 检查业务前端工程；**本库仓无前端，默认跳过** |
| 全项目（业务仓） | 上述 Skill 依次执行 | 仅当工作区为业务工程时 |

### 3.3 报告汇总

报告统一落盘到项目根目录 `_ipc-doc/`，命名与应开发文档对齐（类比 audit 的 `_feat-doc/{YYYYMMDD}_{需求名称}/audit.md`）：

| 场景 | 输出路径 |
| ---- | -------- |
| 关联应开发文档 | `_ipc-doc/{YYYYMMDD}_{需求名称}-ipc.md` |
| 未关联应开发文档（如全项目巡检） | `_ipc-doc/{YYYYMMDD}_全项目-ipc.md` |

- 目录不存在时先创建 `_ipc-doc/`
- 同名报告已存在时直接覆盖，不另起序号

汇总报告格式：

- **Go 后端巡检结果**：引用 Go代码巡检 输出的问题清单
- **前端巡检结果**：引用 前端代码巡检 输出的问题清单
- **综合评估**：汇总严重/警告/建议问题数量，给出整体质量评估

本 Skill 不自行定义问题级别和巡检口径，所有问题的级别、描述和依据均来自对应子 Skill。

## 4. 约束与规范

- [ ] 本 Skill 只做分发和汇总，不定义巡检规则和问题级别
- [ ] 巡检口径全部由 Go代码巡检 和 前端代码巡检 各自的规范依据决定
- [ ] Go 侧分发执行时，子 Skill 必须遵守 `_prompts/rules/基础库优先使用规则.md`（本 Skill 不另定平行口径）
- [ ] 不得把 OpenSpec / SDD 文档混入巡检输入
- [ ] 汇总报告必须写入 `_ipc-doc/`，文件名遵循 `{应开发文档}-ipc.md` 规则
- [ ] 汇总报告不得篡改子 Skill 的问题级别和描述

---

## 5. 验收标准（DoD）

- [ ] 已按用户指定范围分发到对应 Skill 执行
- [ ] 各子 Skill 已输出独立的问题清单
- [ ] 汇总报告已落盘至 `_ipc-doc/{YYYYMMDD}_{需求名称}-ipc.md`（或全项目场景的对应文件名），包含各维度问题汇总和综合评估
- [ ] 报告中未混入本 Skill 自定的巡检口径
