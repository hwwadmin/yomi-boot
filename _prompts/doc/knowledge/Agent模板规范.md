# Agent模板规范

---

## 0. 文档信息
- **文档名称**: Agent模板规范
- **描述**: 定义项目内 Agent 文档的标准结构、资源加载要求、协作清单写法、工作流程表达方式与完成标准，作为新增或重构 Agent 文档时的统一基线。
- **作者**: zwei
- **创建日期**: 2026-05-11

---

## 1. 文档定位

- **用途**：作为项目内 Agent 文档的静态规范，统一 Agent 的章节结构、职责边界、资源依赖、工作流程和输出要求。
- **边界**：不替代具体 Agent 的业务职责定义，也不替代 Skill、知识文档或规则文档本身。
- **适用对象**：`_prompts/agent/` 下所有新增、重构和评审中的 Agent 文档。

---

## 2. 适用范围与关联

### 2.1 适用范围

- 适用于所有需要在 `_prompts/agent/` 下新增或维护的 Agent 文档。
- 重点约束 Agent 的基础结构、资源引用口径、任务执行节奏与职责边界。
- 不用于承载执行型工作流本体；具体执行步骤仍应沉淀到对应 Skill 文档中。

### 2.2 关联文档

| 文档 | 关联点 | 说明 |
| ---- | ------ | ---- |
| `_prompts/doc/Skill技能列表.md` | Skill 装载入口 | Agent 需要引用执行型 Skill 时，应先通过技能列表定位可用 Skill |
| `_prompts/doc/知识库索引.md` | 知识文档装载入口 | Agent 需要引用静态规范、说明或方案类文档时，应先通过知识库索引定位 |
| `_prompts/rules/资源根目录规则.md` | `_prompts` 落点 | 约束 `_prompts` 一律解析为 yomi-boot 脚手架仓；业务仓只挂 commands |
| `_prompts/rules/基础库优先使用规则.md` | 基础库复用 | 约束涉及 Go 基础设施时先读能力索引、核对源码，满足则强制使用 yomi-boot 库 |
| `_prompts/rules/技能加载规则.md` | Skill 读取约束 | 约束 Agent 先查技能列表，再按需加载 Skill |
| `_prompts/rules/知识库加载规则.md` | 知识检索约束 | 约束 Agent 先查知识库索引，再按需加载知识文档 |
| `_prompts/doc/基础库能力索引.md` | 能力速查入口 | 各基础库职责简述与目录落位 |

### 2.3 阅读建议

- 新建 Agent 前，先阅读本规范中的“标准结构”和“资源清单写法”章节。
- 重构已有 Agent 时，优先检查职责边界、资源引用路径和工作流程是否符合本规范。
- 评审 Agent 文档时，重点核对是否保留模板痕迹、是否存在无依据资源引用，以及是否写清“不负责”边界。

## 3. 技术方案

### 3.1 标准结构

所有 Agent 文档应优先采用以下标准结构：

```text
1. 职责定义
2. 规则
3. 协作资源清单
4. 子 Agent 清单（可选）
5. 工作流程
6. 约束与完成标准
```

规则如下：

- `1. 职责定义`、`2. 规则`、`3. 协作资源清单`、`5. 工作流程`、`6. 约束与完成标准` 为默认保留章节。
- `4. 子 Agent 清单` 仅在当前 Agent 负责分派、协调或编排其他 Agent 时保留。
- 若当前 Agent 的任务极其简单，也不得退化为只保留标题和占位表格的空模板。

### 3.2 职责定义写法

职责定义章节至少应包含以下字段：

- **角色描述**：说明当前 Agent 服务的任务类型和在系统中的角色。
- **user_id**：用于关联用户记忆，避免写成无意义占位说明。
- **核心职责**：列出 3-5 条真正执行的动作，要求可验证、可复核。
- **不负责**：显式写出边界，避免与父 Agent、子 Agent、Skill 或其他执行 Agent 产生重叠。

禁止写法：

- 只有“负责处理任务”这类空泛描述，没有任务范围。
- 不写“不负责”，导致职责边界模糊。
- 将业务规范、执行步骤混入“职责定义”章节，导致章节含义混乱。

### 3.3 规则章节写法

规则章节用于声明当前 Agent 的装载前提与执行前约束，至少应覆盖：

- **必须先阅读** `_prompts/rules/资源根目录规则.md`，再阅读 `_prompts/rules/` 下其余规则（含 `基础库优先使用规则.md`），然后执行任务。
- 需要 Skill 时，先通过 `_prompts/doc/Skill技能列表.md` 装载。
- 需要知识文档时，先通过 `_prompts/doc/知识库索引.md` 装载。
- 涉及 Go 基础设施选型、设计或编码时，必须遵守 `基础库优先使用规则.md`：先读 `_prompts/doc/基础库能力索引.md`，有候选则读源码，满足则强制使用 yomi-boot 对应库。
- 禁止脱离当前任务范围无关加载资源。

规则章节应描述“如何装载和遵守约束”，而不是复制规则正文内容（含资源根定义，一律以 `资源根目录规则.md` 为准；基础库复用流程以 `基础库优先使用规则.md` 为准）。

### 3.4 协作资源清单写法

协作资源清单统一使用三列表头：

| 类型 | 名称 | 职责 |
| ---- | ---- | ---- |

填写规则：

- **类型**：仅填写真实资源类型，如“知识文档”“Skill”“Agent”。
- **名称**：填写资源的正式名称，不使用模糊简称。
- **职责**：说明该资源对当前 Agent 的作用，而不是复制文档标题。

示例：

| 类型 | 名称 | 职责 |
| ---- | ---- | ---- |
| 知识文档 | React代码规范 | 作为前端分层、类型建模、接口契约和静态检查的实现依据 |
| Skill | 代码巡检 | 定义巡检流程、检查维度和报告格式 |

禁止写法：

- 只写名称，不写资源职责。
- 把不存在或未被当前 Agent 使用的资源机械列入表格。
- 保留“— / — / —”等占位行作为正式内容。

### 3.5 子 Agent 清单写法

仅当 Agent 具备任务编排或分发职责时，保留本节。

标准表头如下：

| Agent 名称 | 职责 | 触发条件 |
| ---------- | ---- | -------- |

填写规则：

- `Agent 名称` 填写真实存在的 Agent 文档名称。
- `职责` 说明子 Agent 被调用时承担的动作。
- `触发条件` 说明什么情况下由当前 Agent 分派到该子 Agent。

如果当前 Agent 不负责任务分发，应删除本节，而不是保留空表。

### 3.6 工作流程写法

工作流程章节应按照任务推进顺序描述，建议采用 `Step N - 动作名称` 的形式，常见基线如下：

- **Step 1 - 任务确认**：明确用户目标、范围、输入物和输出要求。
- **Step 2 - 规则与资源加载**：先读取规则，再按需加载 Skill、知识文档和代码上下文。
- **Step 3 - 上下文收集**：确认项目结构、模块边界、现有实现和依赖关系。
- **Step 4 - 执行任务**：完成分析、实现、巡检、协调或输出动作。
- **Step 5 - 验证结果**：执行编译、测试、检索或人工校验步骤。
- **Step 6 - 结果输出**：仅输出与任务相关的结论、产物和后续动作。

要求：

- 步骤名称要与当前 Agent 的职责相匹配。
- 不得把不存在的编译、测试或子 Agent 分派步骤硬塞进文档。
- 若当前 Agent 不修改代码，应把验证动作写成检索、比对、报告校验等真实可执行动作。

### 3.7 约束与完成标准写法

该章节用于写清 Agent 的行为边界和完成判定，至少应覆盖：

- 不得跳过规则、技能列表或知识库索引做无依据判断。
- 不得输出无法复核的结论。
- 若不改代码，必须明确“不修改代码”的边界。
- 若负责实现，必须写出最小可执行验证方式。
- 定稿前必须删除不适用的占位说明与示例内容，避免保留模板痕迹。

### 3.8 命名与存放规则

- Agent 正式文档统一存放在 `_prompts/agent/`。
- 文件名应与职责语义一致，优先采用 `{领域或角色}-agent.md` 的写法。
- 静态规范、模板说明、编写要求等内容不应继续放在 `_prompts/agent/`，应沉淀到知识库。

---

## 4. 检查清单

新增或重构 Agent 文档前，请确认：

- [ ] 文档位于 `_prompts/agent/`，且文件名与职责语义一致
- [ ] 已按本规范使用标准章节结构
- [ ] 已写清角色描述、核心职责与不负责边界
- [ ] 协作资源清单只保留真实使用的资源，且填写了职责说明
- [ ] 不负责任务分发时，已删除“子 Agent 清单”章节
- [ ] 工作流程步骤与当前 Agent 的真实职责一致
- [ ] 已删除所有不适用的占位说明、示例表格和模板痕迹

---

## 5. 禁止项

- 禁止将静态规范继续伪装成“模板”长期放在 `_prompts/agent/` 中。
- 禁止复制 Skill、知识文档或规则正文到 Agent 文档中，代替资源引用。
- 禁止列出与当前 Agent 无关的 Skill、知识文档或子 Agent，制造虚假依赖。
- 禁止只保留空标题、空表格和占位语句后直接发布。
- 禁止使用已经失效的路径或旧目录结构。
