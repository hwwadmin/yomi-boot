- **文档名称**: React注释规范
- **描述**: 统一 React 前端代码注释口径，覆盖文件头注释、类型注释、Hook 注释、Domain/API 注释和关键步骤注释写法。
- **作者**: zwei
- **创建日期**: 2026-05-22

## 1. 文档定位

- **用途**：作为**业务前端工程**注释口径的单一事实来源，统一 React 项目中注释的写法、落位和最小覆盖范围。
- **边界**：本文不替代分层、状态管理、国际化和样式规范；这些规范只描述职责与边界，具体注释写法统一以本文为准。
- **适用对象**：业务前端工程的开发、重构、注释整理、代码评审和巡检场景（**yomi-boot 本仓无前端**）。

- 适用于前端项目 `src/` 下的 `page.tsx`、`components/*.tsx`、`hooks/*.ts`、`domain/*.ts`、`api/*.ts`、`types/*.ts`、`store/*.ts` 以及承载业务转换的共享工具文件。
- 重点覆盖文件头注释、类型与字段注释、Hook/Store 暴露项注释、Domain/API 方法注释和方法体关键步骤注释。
- 不要求为显而易见的 JSX 结构、普通样式绑定或同名直译代码添加冗余注释。

## 3. 注释规范

### 3.1 基本原则

| 规则 | 要求 | 说明 |
| ---- | ---- | ---- |
| 语言 | 注释必须使用中文 | 禁止英文注释或中英混写注释 |
| 默认形式 | 默认使用单行 `// 注释` | 除文件头块注释外，优先使用单行注释 |
| 作者前缀 | 单行注释不使用 `zwei：` 等作者前缀 | 作者信息只出现在文件头块注释中 |
| 句号 | 非断句场景不强制句末句号 | 保持短句、直述和可扫读性 |
| 注释目标 | 注释意图、边界、前置条件、关键步骤 | 不重复翻译变量名和显而易见的代码 |
| 先后顺序 | 优先改进命名和拆分，再补注释 | 注释不能用来掩盖混乱结构 |
| 风格一致 | 同一文件中的注释风格保持一致 | 避免同层语义混用多种写法 |

### 3.2 文件头注释

以下文件默认保留中文块注释，并通过 `@author zwei` 标明作者：

1. `hooks/*.ts`
2. `domain/*.ts`
3. `api/*.ts`
4. `types/*.ts`
5. `store/*.ts`
6. `components/*.tsx`
7. 承载业务转换、状态协调或请求封装的共享工具文件

示例：

```typescript
/**
 * 登录页状态协调 Hook
 *
 * @author zwei
 */
export function useLoginPageController() {
  return {}
}
```

### 3.3 类型与字段注释

| 场景 | 要求 |
| ---- | ---- |
| 自定义 `interface` / `type` | 声明上方必须写中文单行注释 |
| 关键字段 | 字段上方写中文单行注释，说明业务语义或用途 |
| 非显而易见映射 | 标签映射、状态映射、表单值对象等应写明注释说明用途 |

示例：

```typescript
// 登录表单值
export interface LoginFormValues {
  // 用户名
  username: string

  // 密码
  password: string
}
```

### 3.4 Hook 与 Store 注释

Hook 和 Store 中以下内容必须写中文单行注释：

1. 状态字段
2. 派生值
3. 对外暴露的方法
4. 方法体中的关键步骤

关键步骤包括但不限于：初始化锁、参数归一化、状态写入、Store 交互、路由跳转、错误兜底、异步请求前后处理、Domain 调用结果回写。

示例：

```typescript
/**
 * 登录页状态协调 Hook
 *
 * @author zwei
 */
export function useLoginPageController() {
  // 登录中状态
  const [loading, setLoading] = useState(false)

  // 提交登录表单
  const handleLogin = async () => {
    // 提交前加锁，避免重复请求
    setLoading(true)

    try {
      // 这里执行登录请求
    } finally {
      // 请求结束后释放加载状态
      setLoading(false)
    }
  }

  return {
    loading,
    handleLogin,
  }
}
```

### 3.5 Domain 与 API 注释

| 场景 | 要求 |
| ---- | ---- |
| 导出的纯逻辑函数 | 方法上方写注释，说明规则意图或转换目的 |
| API 请求方法 | 方法上方写注释，说明请求职责或接口用途 |
| 关键转换步骤 | 数据整形、兜底、分支裁剪、响应解释等重点步骤前写注释 |

### 3.6 Page 与 Component 注释

`page.tsx` 和 `components/*.tsx` 默认依靠清晰的组件名、变量名和拆分结构表达语义，不要求为普通 JSX 结构逐行补注释。

文件头要求：

1. `components/*.tsx` 至少保留一个文件头块注释，说明当前组件职责。
2. 该文件头块注释仍需包含 `@author zwei`。

仅在以下情况添加单行注释：

1. 复杂条件渲染分支
2. 非直观的事件绑定链路
3. 带业务约束的展示块装配
4. 临时兜底或兼容性处理

禁止在简单的标签结构、普通 Props 透传和显而易见的布局片段前堆砌注释。

### 3.7 禁止事项

- 禁止使用英文注释或中英混杂注释
- 禁止在单行注释中使用 `zwei：`、`author:` 等作者前缀
- 禁止注释显而易见的赋值、渲染和变量透传
- 禁止把历史变更说明、沟通记录或待办事项长期留在代码注释中
- 禁止同一语义层同时混用块注释、单行注释和行尾注释表达同一件事

## 4. 检查清单

- [ ] `hooks`、`domain`、`api`、`types`、`store` 文件已具备文件头块注释并包含 `@author zwei`
- [ ] 自定义 `interface` / `type` 及关键字段已写明中文单行注释
- [ ] Hook / Store 的状态字段、派生值、暴露方法已写明中文单行注释
- [ ] Domain / API 的导出方法和关键步骤已写明中文单行注释
- [ ] Page / Component 中只对复杂装配或关键分支添加必要注释，无冗余注释
- [ ] 单行注释统一使用 `// 注释`，未出现 `zwei：` 前缀和风格混杂

- [ ] 文件头块注释、单行注释和关键步骤注释的风格保持一致
