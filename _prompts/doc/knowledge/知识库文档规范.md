# 知识库文档规范

---

## 0. 文档信息
- **文档名称**: 知识库文档规范
- **描述**: 定义项目内知识库文档的标准结构、命名与存放规则、索引登记方式、正文写法与引用口径，作为新增或重构知识库文档时的统一规范基线。
- **作者**: zwei
- **创建日期**: 2026-05-11

---

## 1. 文档定位

- **用途**：作为项目内知识库文档的静态规范，统一知识库文档的章节结构、元信息、正文组织、索引接入和引用方式。
- **边界**：不替代具体知识文档本身的业务内容，也不替代 Skill 文档、Agent 文档或规则文档的执行要求。
- **适用对象**：`_prompts/doc/knowledge/` 下所有新增、重构和评审中的知识库文档。

---

## 2. 适用范围与关联

### 2.1 适用范围

- 适用于所有需要沉淀到 `_prompts/doc/knowledge/` 的静态知识文档。
- 重点约束知识库文档的基础结构、命名方式、索引登记、正文骨架与引用口径。
- 不用于承载具体任务执行流程；执行流程应沉淀到 `_prompts/doc/skills/` 下的 Skill 文档。

### 2.2 关联文档

| 文档 | 关联点 | 说明 |
| ---- | ------ | ---- |
| `_prompts/doc/知识库索引.md` | 索引登记入口 | 所有知识库文档创建后都应登记到知识库索引 |
| `_prompts/rules/知识库加载规则.md` | 知识加载约束 | 约束先查知识库索引，再按需加载目标知识文档 |
| `_prompts/doc/knowledge/Skill创建规范.md` | Skill 文档基线 | 用于区分静态知识文档与执行型 Skill 的边界，并约束 Skill 的标准结构与创建流程 |
| `_prompts/doc/knowledge/Agent模板规范.md` | Agent 文档基线 | 用于区分知识库规范与 Agent 文档编写规范 |

### 2.3 阅读建议

- 新建知识库文档前，先阅读“标准结构”“正文骨架选择”和“命名与存放规则”章节。
- 重构已有知识库文档时，优先检查是否保留旧目录痕迹、是否写入多余元信息、是否完成索引登记。
- 评审知识库文档时，重点核对命名、结构、引用路径和正文是否仍带执行流程语义。

## 3. 技术方案

### 3.1 标准结构

所有知识库文档应优先采用以下标准结构：

```text
0. 文档信息
1. 文档定位
2. 适用范围与关联
3. 技术方案 / 正文主体
4. 检查清单（可选）
5. 禁止项（可选）
```

规则如下：

- `0. 文档信息`、`1. 文档定位`、`2. 适用范围与关联`、`3. 技术方案 / 正文主体` 为默认保留章节。
- `4. 检查清单`、`5. 禁止项` 适用于模板规范类或规则型知识文档；若正文天然不需要，可按需删除。
- 知识库文档不再维护“迁移说明”等历史过程字段，只保留当前有效信息。
- 不得保留与当前文档无关的占位标题、空表格、空代码块或“待补充”字样。

### 3.2 文档信息写法

`0. 文档信息` 章节至少应包含以下字段：

- **文档名称**：与文件名一致。
- **文档名称**：直接取文件名（不含 `.md`）。
- **描述**：一句话说明文档承载的核心知识边界。
- **作者**、**创建日期**：用于标识文档元信息。

要求：

- 描述必须能直接用于知识库索引展示，禁止写成空泛口号。
- 不新增“迁移说明”“原路径”“旧文件名”等过程性字段。

### 3.3 文档定位写法

`1. 文档定位` 章节统一包含以下三个部分：

- **用途**：说明该文档解决什么问题、承载什么知识。
- **边界**：说明文档不负责什么，避免与其他文档重叠。
- **适用对象**：说明适用目录、模块、角色或场景。

禁止写法：

- 只有“用于指导开发”这类空泛描述，没有明确知识边界。
- 不写“边界”，导致与 Skill、Agent、规则文档职责混淆。
- 把执行步骤直接写进文档定位章节，导致章节语义混乱。

### 3.4 适用范围与关联写法

`2. 适用范围与关联` 章节建议拆为以下小节：

- `2.1 适用范围`
- `2.2 关联文档`
- `2.3 阅读建议`

填写规则：

- `2.1` 说明适用对象、覆盖范围和不适用边界。
- `2.2` 统一使用表头 `文档 / 关联点 / 说明`，引用知识文档时使用 `_prompts/doc/knowledge/` 路径。
- `2.3` 说明阅读顺序、进入时机或与其它知识文档的配合关系。

### 3.5 正文骨架选择规则

知识库正文应根据文档类型选择最贴近的骨架，不得机械套用同一种写法。

| 文档类型 | 适用场景 | 推荐写法 |
| -------- | -------- | -------- |
| 规范文档 | 如 API编码适配规范 | 按主题分节展开规则、约束、示例与边界 |
| 说明文档 | 如架构背景说明 | 先交代背景，再说明方案、选择理由与适用边界 |
| 方案文档 | 如领域演进方案 | 按目标、路径、分阶段方案、风险与建议展开 |
| 模板规范类 | 如 Skill创建规范、Agent模板规范 | 以标准结构、章节写法、检查清单和禁止项为主 |

### 3.6 正文写法要求

正文写作应满足以下要求：

- 优先按真实主题分节，而不是为了凑结构保留空标题。
- 规则、示例、表格和代码块必须与结论一致，不得互相冲突。
- 若引用其他知识文档、规则或目录路径，必须使用当前仓库真实路径。
- 静态知识文档应强调定义、边界、原则、结构和示例，不应写成“接到任务后先做什么”的执行指令集。
- **权威归位**：主题细则只在 `_prompts/doc/知识库索引.md`「权威分工」表所列文档展开；他处仅一句摘要 + 链接。术语以索引「统一术语」表为准，禁止另立冲突口径。

### 3.7 命名与存放规则

- 知识库文档统一存放在 `_prompts/doc/knowledge/` 及其按技术域划分的子目录中。
- 如存在明显技术域归类，可在 `_prompts/doc/knowledge/` 下建立子目录，例如 `_prompts/doc/knowledge/js/`。
- 规范类文档以“规范”结尾。
- 说明类、方案类文档按主题命名，不强制追加“规范”。
- 正文中的“文档名称”应与文件名（不含 `.md`）一致，不得混用旧名与新名。

### 3.8 索引登记规则

所有知识库文档创建后，都必须登记到 `_prompts/doc/知识库索引.md`。

索引表格统一包含以下字段：

- **名称**：文档名称。
- **描述**：对文档内容的简要概括。
- **目录地址**：知识库文档的相对路径。

要求：

- 索引中的描述应可帮助调用方快速判断是否需要加载该文档。
- 目录地址应使用文档真实落位路径，例如 `_prompts/doc/knowledge/{文件名}.md` 或 `_prompts/doc/knowledge/js/{文件名}.md`；相对链接也需与真实落位保持一致，例如 `./knowledge/{文件名}.md` 或 `./knowledge/js/{文件名}.md`。

### 3.9 引用与链接规则

- 知识库文档之间互相引用时，应优先使用 `_prompts/doc/knowledge/` 路径，并补全真实子目录。
- 被 Skill 或 Agent 引用时，也应通过知识库路径引用，而不是使用历史目录或根目录旧路径。
- 不得继续引用已经删除或迁出的旧路径。

---

## 4. 检查清单

新增或重构知识库文档前，请确认：

- [ ] 文档位于 `_prompts/doc/knowledge/` 或其子目录中，且文档名称与文件名（不含 `.md`）一致
- [ ] 已按本规范使用标准章节结构
- [ ] 已写清用途、边界和适用对象
- [ ] 已按实际文档类型选择正文骨架，而不是机械套模板
- [ ] 关联文档和目录路径均使用当前仓库真实路径
- [ ] 已完成知识库索引登记
- [ ] 已删除所有不适用的占位说明、空表格、空代码块和历史过程字段

---

## 5. 禁止项

- 禁止将执行流程、任务步骤或操作说明直接写成知识库文档主体，伪装成静态规范。
- 禁止保留“迁移说明”“原路径”“旧文件名”等过程性元信息。
- 禁止知识库文档不登记到知识库索引，导致无法被标准流程发现。
- 禁止复制其他知识文档正文，制造重复来源。
- 禁止使用已失效的路径、旧目录结构或失真的文档名称。
