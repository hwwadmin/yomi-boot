# Skill创建规范

---

## 0. 文档信息
- **文档名称**: Skill创建规范
- **描述**: 定义 Skill 文档的标准结构、章节写法、正文骨架选择规则、创建流程、归类判断规则、目录落位方式与技能列表登记要求，作为新增或重构执行型 Skill 时的统一规范基线。
- **作者**: zwei
- **创建日期**: 2026-06-02

---

## 1. 文档定位

- **用途**：作为项目内执行型 Skill 文档的单一规范基线，统一 Skill 的章节结构、依赖表达、正文骨架选择、创建流程、归类判断、目录落位、登记要求和验收口径。
- **边界**：不替代具体 Skill 的业务规则、执行流程或实现方案；这些内容仍应在对应 Skill 正文中按需编写。
- **适用对象**：`_prompts/doc/skills/` 下所有新增、重构和评审中的 Skill 文档，以及需要判断主题是否适合写成 Skill 的决策场景。

---

## 2. 适用范围与关联

### 2.1 适用范围

- 适用于所有需要在 `_prompts/doc/skills/` 下新增或维护的执行型 Skill 文档。
- 重点约束 Skill 的基础信息、标准结构、各章节写法、依赖清单、正文骨架选择、创建流程、归类判断、输出要求、验收标准以及技能列表登记。
- 不用于承载静态规范、原则或基线；这类内容应沉淀到知识库。

### 2.2 关联文档

| 文档 | 关联点 | 说明 |
| ---- | ------ | ---- |
| `_prompts/doc/knowledge/知识库文档规范.md` | 知识文档基线 | 当主题被判定为知识库文档或混合型主题时，按此规范编写知识文档 |
| `_prompts/doc/Skill技能列表.md` | 技能登记入口 | Skill 创建完成后必须在此列表登记目录地址 |
| `_prompts/doc/知识库索引.md` | 知识分流入口 | 当主题涉及知识文档分流时，需同步登记到知识库索引 |
| `_prompts/rules/基础库优先使用规则.md` | 基础库复用 | 涉及 Go 基础设施的 Skill 必须遵守；先读能力索引再选型 |
| `_prompts/doc/基础库能力索引.md` | 能力速查入口 | 各基础库职责简述与目录落位 |

### 2.3 阅读建议

- 新建 Skill 前，先阅读"标准结构"和"正文骨架选择"章节，确定文档框架。
- 收到创建 Skill 的请求后，先阅读"文档归类规则"章节，判断主题是否真的适合写成 Skill。
- 确认为执行型 Skill 后，再按"创建流程"章节逐步执行。
- 重构已有 Skill 时，优先检查依赖清单、正文骨架和约定即可。

## 3. 技术方案

### 3.1 标准结构

所有 Skill 文档应优先采用以下标准结构：

```text
0. 基础信息
1. 目标
2. 输入/依赖
3. 技术方案
4. 输出文档规范（可选）
5. 约束与规范
6. 验收标准（DoD）
```

规则如下：

- `0. 基础信息` 至 `3. 技术方案`、`5. 约束与规范`、`6. 验收标准（DoD）` 为默认保留章节。
- `4. 输出文档规范` 仅在 Skill 直接产出 spec、报告、清单或方案文档时保留。
- Skill 文档正文不再维护唯一标识；若仓库仍需要唯一标识，仅在 `Skill技能列表.md` 中维护。
- 不得保留与当前 Skill 无关的占位标题、空表格、空代码块或"待补充"字样。

### 3.2 基础信息写法

`0. 基础信息` 章节至少应包含以下字段：

- **Skill 名称**：与文件名一致。
- **描述**：一句话写清输入、输出和核心边界。
- **作者**、**创建日期**：用于登记 Skill 的基本元信息。

要求：

- 描述必须可用于技能列表展示，禁止写成空泛口号。

### 3.3 目标章节写法

`1. 目标` 章节统一包含以下三个部分：

- **做什么**：说明 Skill 的核心产出或动作。
- **为什么**：说明业务价值、协作价值或质量收益。
- **不做什么**：列出 2–3 条明确边界。

禁止写法：

- 只写"用于完成任务"这类空泛描述。
- 不写"不做什么"，导致 Skill 边界失控。
- 把执行步骤直接混入目标章节，导致章节语义混乱。

### 3.4 输入/依赖章节写法

`2. 输入/依赖` 章节应按以下小节组织：

- `2.0 调用方式与输入（可选）`
- `2.1 前置 Skill 依赖`
- `2.2 知识文档依赖`
- `2.3 代码与配置依赖（按需新增）`
- `2.4 数据表依赖（按需顺延）`

填写规则：

- `2.0` 仅适用于动作型、转换型、巡检型或输出文档型 Skill。
- `2.1` 统一使用表头 `名称 / 状态 / 说明`。
- `2.2` 统一使用表头 `文档 / 关联点 / 说明`，引用知识文档时使用 `_prompts/doc/knowledge/` 路径。
- 若无前置依赖或额外知识依赖，可显式写"无"，但不得留空。
- 若依赖路由处理器、请求模型、配置文件或框架类定义，应新增"代码与配置依赖"小节，而不是塞进知识文档依赖表。

### 3.5 正文骨架选择规则

Skill 正文应根据实际类型选择最贴近的骨架，不得机械保留历史模板的全部分支。

| Skill 类型 | 适用场景 | 推荐写法 |
| ---------- | -------- | -------- |
| 流程执行型 | 如代码巡检、接口测试、批量检查类 Skill | 先写执行流程，再逐阶段说明检查项、方法和输出 |
| 实现设计型 | 需要同时描述后端、前端、接口、状态等方案的 Skill | 按需保留后端设计 / 前端设计，不涉及的一侧直接删除 |
| 输出文档型 | 如需求显化、报告生成、方案归纳类 Skill | 明确输入、输出文件路径、章节要求和禁止输出项 |
| 规则清单型 | 执行型 Skill 内部仍需列出检查清单、执行规则或输出约束 | 使用表格、清单和示例代码块展开规则主题 |
| 静态规范型 | 如 React代码规范、数据库表设计规范 | 不应创建为 Skill，应改建知识库文档并登记知识库索引 |

### 3.6 各类型正文写法

#### 3.6.1 规则清单型正文写法

适用于执行型 Skill 内部仍需列出检查清单、输出约束或执行规则的场景。

要求：

- 按真实规则主题分组，而不是为了凑模板强行保留空表格。
- 每个规则主题应包含"规则/检查项""说明""示例/依据"等最小信息。
- 示例代码块、SQL、JSON 或目录结构必须与正文结论一致。

#### 3.6.2 流程执行型正文写法

适用于"按步骤执行任务"的 Skill，建议先写 ASCII 流程，再写每一阶段的目标、范围和方法。

要求：

- 流程必须反映真实执行顺序，而不是空泛地列出"开始/结束"。
- 每个阶段至少说明目标和执行步骤；如有检查项或输出项，可配表格说明。
- 误报防护、异常处理和输出格式要求，应在对应阶段就地写清。

#### 3.6.3 实现设计型正文写法

仅当 Skill 需要产出实现方案时使用。

要求：

- 后端设计应写清模块归属、包路径、核心对象和动作清单。
- 前端设计应写清页面/组件、状态管理、API 对接和 Mock 数据等信息。
- 若某一侧不涉及，应直接删除对应小节，不得保留空标题或"无"这类占位说明。

#### 3.6.4 输出文档型正文写法

仅适用于直接产出 spec、报告、清单或方案文档的 Skill。

`4. 输出文档规范` 章节应明确：

- 输出路径
- 输出文件
- 必须包含的章节
- 不得包含的内容

如果 Skill 不直接产出文档，应删除本节，而不是保留空模板。

### 3.7 约束与 DoD 写法

`5. 约束与规范` 与 `6. 验收标准（DoD）` 用于写清行为边界和完成判定，至少应覆盖：

- 路径、模块名、包名、类名、表名必须与当前仓库结构一致。
- 若引用其他 Skill、规则或知识文档，需在依赖章节列出来源和用途。
- 凡涉及 Go 基础设施选型、设计或编码的 Skill，必须在约束中声明遵守 `_prompts/rules/基础库优先使用规则.md`（先读 `_prompts/doc/基础库能力索引.md`，有候选则读源码，满足则强制使用 yt-boot 库）。
- 不新增变更日志 / 更新记录章节。
- 标题层级清晰、编号连续，无未删除的模板分支。
- 与 `Skill技能列表.md`、`Skill创建规范.md` 及现有已发布 Skill 的口径保持一致。

### 3.8 命名与存放规则

- 执行型 Skill 文档统一存放在 `_prompts/doc/skills/` 目录下。
- Skill 名称直接取文件名（不含 `.md`），保持执行语义。
- 知识库文档统一存放在 `_prompts/doc/knowledge/` 及其子目录下。
- 静态规范、模板说明和编写要求不应放在 `_prompts/doc/skills/` 中，应归属到知识库。

### 3.9 文档归类规则

收到创建请求后，必须先判断主题属于以下哪一类：

| 类别 | 特征 | 目标 | 落位目录 |
| ---- | ---- | ---- | -------- |
| 执行型 Skill | 目标是"做事"，有明确输入、执行步骤、输出要求和 DoD | 按本规范编写 Skill 文档 | `_prompts/doc/skills/` |
| 知识库文档 | 目标是沉淀静态规范、原则、基线或说明方案 | 按 知识库文档规范 编写知识文档 | `_prompts/doc/knowledge/` |
| 混合型主题 | 既需要静态规则，又需要执行流程 | 拆成"知识库文档 + 执行型 Skill"两份文档 | 各自落位 |

处理规则如下：

1. 如果判定为知识库文档，停止继续创建 Skill，转为按 知识库文档规范 编写文档。
2. 如果判定为混合型主题，先沉淀知识文档，再单独编写执行型 Skill，两者不得使用同名文档。
3. 只有明确属于执行型 Skill 的主题，才继续后续创建流程。

### 3.10 创建流程

执行型 Skill 的创建按以下步骤执行：

1. **检查是否已有同类 Skill**：先在 `_prompts/doc/Skill技能列表.md` 中检索，避免重复创建。
2. **确定最终文件名**：先确定最终文件名，再以该文件名（不含 `.md`）作为 Skill 名称。
3. **选择正文骨架**：以本文 §3.5 的骨架选择规则为准，只保留当前 Skill 真实需要的章节。
4. **写清目标与边界**：在"目标"章节明确做什么、为什么、不做什么。
5. **列出真实依赖**：区分前置 Skill、知识文档、文件目录等依赖，不留空占位。
6. **补正文与输出要求**：按 Skill 类型组织正文，若直接产出文档则补充输出规范。
7. **登记技能列表**：同步更新 `_prompts/doc/Skill技能列表.md`。

### 3.11 技能列表登记规则

Skill 创建完成后，必须同步更新 `_prompts/doc/Skill技能列表.md`。登记要求如下：

- **技能列表登记 ID** 使用 `YYYYMMDD_时间戳` 格式，仅在技能列表中维护。
- **名称** 直接取 Skill 文件名（不含 `.md`）。
- **描述** 要能直接表达输入、动作和产出，避免口号化表述。
- **目录地址** 统一填写 `./skills/{Skill名称}.md`。
- **作者**、**创建日期** 要与 Skill 文档正文保持一致。

## 4. 检查清单

新增或重构 Skill 文档前，请确认：

- [ ] 文档位于 `_prompts/doc/skills/`，且 Skill 名称与文件名（不含 `.md`）一致
- [ ] 已按本规范使用标准章节结构
- [ ] 已写清目标、边界、依赖、正文和 DoD
- [ ] 依赖清单只保留真实使用的 Skill、知识文档、代码或数据表依赖
- [ ] 已按实际类型选择正文骨架，而不是机械保留全部模板分支
- [ ] 若不直接产出文档，已删除"输出文档规范"章节
- [ ] 已按归类规则判断主题类型，未把静态规范误写成 Skill
- [ ] 创建流程已按步骤执行，未跳过技能列表检索
- [ ] 命名与存放符合目录归属规则
- [ ] 技能列表登记信息与文档正文保持一致
- [ ] 已删除所有不适用的占位说明、空表格、空代码块和模板痕迹

---

## 5. 禁止项

- 禁止将静态规范伪装成执行型 Skill 发布到 `_prompts/doc/skills/`。
- 禁止复制知识文档或规则正文进 Skill，代替依赖引用。
- 禁止只创建 Skill 文档但不更新技能列表。
- 禁止在 Skill 文档中保留空章节、模板占位或失效路径。
- 禁止保留与当前 Skill 无关的后端设计、前端设计、输出文档或数据表占位分支，包括仅写"无"的占位小节。
- 禁止在 Skill 正文中继续维护唯一标识。
- 禁止使用已失效的目录结构或旧路径。
